# TaskMaster

プロジェクト・タスク・サブタスク（無制限階層）・タグ・優先度・期限を管理できるデスクトップ版タスク管理アプリ（Python + CustomTkinter）。ドラッグ&ドロップによる並び替え、ツリー/カンバン/ガントの3ビュー、統計ダッシュボードを備える。画面上のテキストはすべて日本語。Nuitkaで単一の `TaskMaster.exe` にビルドでき、利用者はPython・Node.jsいずれのインストールも不要。

## ブランチ構成

- `develop/v1` — 旧`develop`ブランチを保存したもの。Node.js/TypeScript（Express+Prisma+React）版の最終状態を凍結しており、今後の変更は加えない。
- `develop/v2` — 現在のリポジトリのデフォルトブランチ。`develop/v1`と同じコミットから分岐しており、Python+CustomTkinter版の開発はこちらで行う。

## 画面要件

### 共通レイアウト

| 要素 | 内容 |
|---|---|
| サイドバー | ダッシュボード／プロジェクト一覧／設定へのリンク、プロジェクトのナビゲーション（アーカイブ済みは非表示） |
| メインエリア | 選択中の画面を表示（クリックで画面が切り替わる） |

### ① ダッシュボード

全プロジェクト横断の概要画面。

- 統計カード：プロジェクト数（アーカイブ除く）、直近7日の完了数、タスク総数、完了率、期限超過件数、7日以内に期限を迎える件数
- 期限超過タスク一覧（最大8件、期限が近い順）
- 期限が近いタスク一覧（最大8件）
- プロジェクト一覧（プロジェクト名・色・タスク件数、クリックで詳細へ）

### ② プロジェクト一覧

- 「+ 新しいプロジェクト」からプロジェクトを作成
- プロジェクトごとに 編集／アーカイブ・復元／削除
- アーカイブしたプロジェクトはサイドバー・ダッシュボードから非表示になる（「アーカイブ済みも表示」チェックで表示・復元できる）

### ③ プロジェクト詳細

- ヘッダー：プロジェクト名・説明・「ツリー / カンバン / ガント」表示切替・「+ 新しいタスク」ボタン
- カンバンビュー：
  - ステータスごとの列にタスクカードを表示
  - カードを別の列へドラッグ&ドロップするとステータス変更、同じ列内でドラッグすると並び順を変更
  - カードダブルクリックで編集モーダルが開く
- ガントチャートビュー：
  - タスクを行、日付を列として、開始日〜期限の期間をステータス色のバーで表示
  - 月・日ヘッダー（土日は色分け）、今日の縦ライン
  - 開始日のみ／期限のみの場合は1日分のバー、両方未設定はバー非表示
  - タスク名・バーのクリックで編集モーダルが開く
- タスクツリー：
  - 親子関係を持つタスクを無制限の深さでネスト表示（展開/折りたたみはネイティブ機能）
  - 右クリックメニューでサブタスク追加・編集・ステータス変更・削除
  - ドラッグで同一階層内の並び替え
  - 期限超過は赤字、完了ステータスはグレー表示
- タスク作成・編集モーダル：タイトル・詳細・ステータス・優先度・開始日・期限・親タスク（階層変更、循環検出あり）・タグ（複数選択＋その場で新規作成、右クリックでタグ自体を削除）
- プロジェクト作成・編集モーダル：名前・説明・カラー選択
- 削除確認ダイアログ（プロジェクト／タスク共通）

### ④ 設定

サイドバー下部の「⚙️ 設定」から開く。ステータス／祝日／タグ／言語の4セクションを持つ。

- **ステータス**：追加・名称変更・カラー変更・並び替え（▲▼）・削除
  - 「完了として扱う」フラグ：付けたステータスは完了率の計算や期限超過の判定で完了済みとして扱われる
  - タスクで使用中のステータス、および最後の1件は削除不可（エラーメッセージ表示）
- **祝日**：ガントチャートの土日祝シェーディングに使用。日付（カレンダー選択／直接入力）・名称を登録、一覧は日付昇順でインライン編集・削除が可能。CSVファイル（列順「日付,名称」）からの一括登録にも対応し、既存の日付と一致する行は名称を上書きする
- **タグ**：プロジェクトを横断して共有される名前・色の一覧。追加・インライン改名・色変更・削除ができる（削除確認ダイアログに使用中タスク件数を表示）。名前の重複はエラーで拒否
- **言語 / Language**：日本語／英語を切替可能。切替は即座にサイドバーや表示中の画面に反映される（選択はDBに保存され、次回起動時も保持される）

## データベース定義

DDL: [app/db/schema.sql](app/db/schema.sql)

### ER概要

```
Project 1───N Task ───N┐
                 │      ├──N TaskTag N──┐
                 ├─self (parentId)      │
                 └──N─1 Status         Tag
```

### Project

| カラム | 型 | 説明 |
|---|---|---|
| id | TEXT | 主キー |
| name | TEXT | プロジェクト名 |
| description | TEXT? | 説明（任意） |
| color | TEXT | 表示色（デフォルト `#6366f1`） |
| archived | INTEGER(bool) | アーカイブフラグ。trueのプロジェクトは各一覧・集計から除外される |
| order | INTEGER | サイドバーでの表示順 |
| createdAt / updatedAt | TEXT(ISO8601) | 管理はアプリケーション側で行う（SQLiteに自動更新トリガーは無い） |

### Task

| カラム | 型 | 説明 |
|---|---|---|
| id | TEXT | 主キー |
| title | TEXT | タスク名 |
| description | TEXT? | 詳細（任意） |
| status | TEXT | `Status.id` への外部キー（`ON DELETE RESTRICT` — 使用中ステータスは削除不可） |
| priority | TEXT | `LOW` \| `MEDIUM` \| `HIGH` \| `URGENT` |
| startDate / dueDate | TEXT? | 開始日・期限（任意、ガントチャートのバーに使用） |
| order | INTEGER | 同一階層内での並び順 |
| projectId | TEXT | 所属プロジェクト（`ON DELETE CASCADE`） |
| parentId | TEXT? | 親タスクへの自己参照。`NULL`なら最上位タスク（`ON DELETE CASCADE`で親削除時に子孫も削除） |

インデックス：`projectId` / `parentId` / `status` / `priority` / `dueDate`

### Status

ユーザーが設定画面で自由に追加・変更できるタスクのステータス。初回起動時に `TODO`（未着手）/ `IN_PROGRESS`（進行中）/ `DONE`（完了）/ `WITHDRAWN`（取下げ）の4件が自動投入される（既存データがある場合は投入しない、非破壊的）。

| カラム | 型 | 説明 |
|---|---|---|
| id | TEXT | 主キー |
| label | TEXT | 表示名 |
| color | TEXT | 表示色 |
| order | INTEGER | 表示順（カンバンの列順） |
| isDone | INTEGER(bool) | 完了扱いフラグ。完了率・期限超過の集計に使われる |

### Tag / TaskTag

`Tag`（id/name一意/color）と `TaskTag`（`taskId`+`tagId`複合主キーの中間テーブル）で多対多を表す。

### Holiday

ガントチャートの土日祝シェーディング・設定画面での管理用。どのテーブルにも従属しない独立した一覧。

| カラム | 型 | 説明 |
|---|---|---|
| id | TEXT | 主キー |
| date | TEXT | `YYYY-MM-DD`。一意制約（CSV一括登録時は一致する日付の行を上書きする） |
| name | TEXT | 祝日名 |

### AppSetting

アプリ全体の設定（言語選択など）を保持する汎用キーバリューテーブル。

| カラム | 型 | 説明 |
|---|---|---|
| key | TEXT | 主キー（例：`language`） |
| value | TEXT | 設定値（例：`ja` / `en`） |

## 使い方

起動後、ウィンドウが開く。`python seed.py` を実行済みならサンプルのプロジェクト・タスクが入った状態で確認できる。

### 1. プロジェクトを作る・アーカイブする

サイドバーの「📁 プロジェクト一覧」から「+ 新しいプロジェクト」で作成。一覧画面で編集・削除・アーカイブができる。アーカイブしたプロジェクトはサイドバー・ダッシュボードに表示されなくなる（データは残り、「アーカイブ済みも表示」で確認・復元できる）。

### 2. タスクを作る・サブタスクを作る

プロジェクト詳細の「+ 新しいタスク」、またはツリー表示で行を右クリックして「+ サブタスクを追加」。サブタスクにさらにサブタスクを追加でき、階層に制限はない。親を変更したい場合はタスクを編集し、「親タスク」欄で選び直す（自分自身やその子孫には移動できない）。

### 3. ステータスを更新する・並び替える

ツリー表示では行を右クリックして「ステータス変更」。ドラッグでの並び替えは同じ親を持つタスク同士でのみ有効（異なる親へは編集モーダルの「親タスク」で移動する）。

### 4. カンバン／ガントで見る

プロジェクト画面上部の切替ボタンで「カンバン」「ガント」に切り替えられる。カンバンはカードを列間・列内でドラッグ、ガントは開始日〜期限のバーで進捗を俯瞰できる。

### 5. ステータス・祝日・タグを自分用に変える

サイドバー下部の「⚙️ 設定」から、ステータスの追加・名称/色の変更・並び替え・削除（「完了として扱う」を付けたステータスが完了率などの集計で「完了」と見なされる）、ガントチャートの土日祝シェーディングに使う祝日の登録（個別追加のほか、CSVの一括読み込みにも対応）、プロジェクトを横断して共有するタグの管理（色・名前の変更、削除）ができる。

### 6. 表示言語を切り替える

「⚙️ 設定」の「言語 / Language」で日本語／英語を切り替えられる。切替は即座に画面全体へ反映され、選択した言語は次回起動時も保持される。

## テスト

pytest のみ（ユニット＋SQLite統合テスト、GUIの自動テストは無し）。

```bash
python -m pytest
```

- **tests/unit** — `app/logic/{tree,dnd,gantt}.py` の純粋関数、`app/i18n.py` の翻訳フォールバックを検証（33件）
- **tests/integration** — `app/db/*.py` をテスト用の一時SQLiteファイルに対して検証。循環参照検出・統計（isDone駆動）・アーカイブ除外・ステータス削除制約・祝日CSV取込・`AppSetting`のCRUDを重点的にカバー（58件）
- **GUI（app/ui/*）** — 自動テストは無し。手動で `python -m app.main` を実行して確認する

いずれのテストも開発用 `taskmaster.db` には触れない（一時ディレクトリに専用DBを作成）。

## exe化（Nuitka）

```bash
python packaging/build_exe.py
```

`packaging/dist/TaskMaster.exe` が生成される（初回はCコンパイラ`zig`のダウンロードが発生し数分かかる）。配布時は `TaskMaster.exe` 単体をコピーするだけでよく、初回起動時に同じフォルダへ `taskmaster.db` が自動生成される（Node.js・Python共にインストール不要）。詳細な制約（`NUITKA_ONEFILE_PARENT`の扱いなど）は [CLAUDE.md](CLAUDE.md) を参照。

## ディレクトリ構成

```
app/
  main.py            # エントリポイント
  i18n.py            # 多言語対応（t()関数・言語切替）
  locales/           # 言語ごとの翻訳辞書（en.py等）
  db/                # SQLite直接操作のデータ層（schema.sql含む）
  logic/             # ツリー構築・DnD計画・ガント計算（純粋関数）
  ui/                # CustomTkinter画面・ウィジェット
tests/
  unit/              # app/logic のテスト
  integration/       # app/db のテスト
packaging/
  build_exe.py       # Nuitkaビルドスクリプト
seed.py              # サンプルデータ投入（破壊的）
```
