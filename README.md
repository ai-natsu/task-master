# TaskMaster

個人の身近なやることリストやタスクリスト（ToDoリスト）のアプリです。
開始日や期限の日付を入れて、進捗率を表示することで、タスク実施のやる気を上げられます。
複数のやることをプロジェクトとして、グループ管理でき、タスクもサブタスクを作れますので、いきなり、大きな目標を立てて、挫折することを予防できます。
画面は、ツリービュー・カンバンビュー・ガントビューがあり、切り替えて使えます。
Windows版とMac版があり、ファイルをダウンロードして、すぐに使えます。
Webアプリ版もあります。

## 1. 機能概要

- プロジェクトを作り、その中でタスクを作って進捗を管理できる
- タスクの下にサブタスクを作れる
- タスクごとにステータス・優先度・開始日・期限・タグを付けられる
- ツリービュー・カンバンビュー・ガントビューを切り替えられ、どのビューでもドラッグで並べ替えができる
- キーワード・ステータス・優先度・タグでタスクを絞り込める
- ダッシュボードで、全プロジェクトの完了率や期限切れのタスクを確認できる
- ステータスの種類、祝日、タグを自分で設定できる
- 画面の表示言語を日本語と英語から選べる
- 使わなくなったプロジェクトはアーカイブにして、非表示にできる

## 3. バージョンについて

TaskMaster には、Webアプリ版（`apps/web`）とデスクトップアプリ版（`apps/desktop`）の2つがあります。どちらも同じリポジトリに入っています。

| | Web版（`apps/web`） | デスクトップ版（`apps/desktop`） |
|---|---|---|
| 形態 | Web アプリ版 | デスクトップアプリ版 |
| 動かし方 | Node.js でサーバーを起動し、ブラウザで http://localhost:3001 を開く | `TaskMaster.exe`（Windows）か `TaskMaster.app`（Mac）を起動する |
| 事前に入れるもの | Node.js 18 以上 | なし |
| 主な技術 | Express・Prisma・React | Python・CustomTkinter |
| データ | `apps/web/server/prisma/dev.db`（SQLite。[9.3](#93-webアプリ版)） | `taskmaster.db`（SQLite。[9.1](#91-windows版)・[9.2](#92-mac版)） |
| ディレクトリ | `apps/web` | `apps/desktop` |

デスクトップ版は、利用者が Node.js を入れずに1つの実行ファイルで使えるよう、Web版を Python で作り直したものです。機能は Web版とほぼ同じです。

## 5. インストール

実行ファイル（`TaskMaster.exe`、`TaskMaster.app`）は、リポジトリには含まれていません。**GitHub の [Releases](https://github.com/ai-natsu/task-master/releases)** に、zip で置いてあります。最新版は [Releases の最新版](https://github.com/ai-natsu/task-master/releases/latest) の「Assets」から取得します。

| 版 | 系統 | 入手先 |
|---|---|---|
| [Windows版](#51-windows版) | desktop | [Releases](https://github.com/ai-natsu/task-master/releases/latest) の `TaskMaster-<版>-win64.zip`（自分でビルドした場合は `apps/desktop/packaging/dist/` にできる） |
| [Mac版(Zip)](#52-mac版zip) | desktop | [Releases](https://github.com/ai-natsu/task-master/releases/latest) の `TaskMaster-<版>-mac.zip`（自分でビルドした場合は `apps/desktop/packaging/dist/` にできる） |
| [Mac版(Homebrew)](#53-mac版homebrew) | desktop | Homebrew |
| [Webアプリ版](#54-webアプリ版) | web | ソースコードをクローンする |


### 5.1 Windows版

Windows版TaskMasterのインストール手順は以下の通りです。

1. [Releases](https://github.com/ai-natsu/task-master/releases/latest) から `TaskMaster-<版>-win64.zip` をダウンロードし、解凍する。`TaskMaster/` フォルダができる。
2. `TaskMaster/` フォルダを好きな場所に置く。ただし `Program Files` など書き込みできない場所には置かない（データを保存できず、起動に失敗する）。

### 5.2 Mac版(Zip)

Mac版(Zip)TaskMasterのインストール手順は以下の通りです。

1. [Releases](https://github.com/ai-natsu/task-master/releases/latest) から `TaskMaster-<版>-mac.zip` をダウンロードし、解凍する。`TaskMaster/` フォルダができる。
2. `TaskMaster/` フォルダを好きな場所に置く。

### 5.3 Mac版(Homebrew)

Mac版(Homebrew)TaskMasterのインストール手順は以下の通りです。

1. [Homebrew](https://brew.sh/) が入っていることを確認する。
2. ターミナルで次を実行する。どのフォルダで実行してもよい。

   ```bash
   brew tap ai-natsu/task-master https://github.com/ai-natsu/task-master
   brew install --cask taskmaster
   ```

3. `TaskMaster.app` が「アプリケーション」フォルダ（`/Applications`）に入る。

インストールした後は、次のコマンドで更新やアンインストールができる。

| 内容 | コマンド |
|---|---|
| 新しい版にする | `brew upgrade --cask taskmaster` |
| アンインストールする（データは残る） | `brew uninstall --cask taskmaster` |
| アンインストールし、データも消す | `brew uninstall --zap --cask taskmaster` |

### 5.4 Webアプリ版

Webアプリ版TaskMasterは、ブラウザでWebサーバーへアクセスして、アプリを利用します。Webサーバーとブラウザは同じPCで問題ありません。

Webサーバーのインストール手順は以下の通りです。

1. サーバーの実行環境の Node.js 18 以上をインストールする。次のコマンドで、インストールされているか確認できる。

   ```bash
   node -v
   ```

   バージョンが表示されなければ、インストールされていない。次のコマンドでインストールする。インストールしたら、ターミナルを開き直す。

   | 環境 | コマンド |
   |---|---|
   | Windows（PowerShell） | `winget install OpenJS.NodeJS.LTS` |
   | Mac（Homebrew） | `brew install node` |
   | Linux（nvm） | `nvm install --lts` |

   コマンドを使わない場合は、https://nodejs.org/ から「LTS」のインストーラーをダウンロードして実行する。

2. ターミナルで、ソースコードを置きたいフォルダに移動し、次を実行する。`task-master` フォルダができる。

   ```bash
   git clone https://github.com/ai-natsu/task-master.git
   cd task-master/apps/web
   ```

3. 起動方法は [6.4](#64-webアプリ版) を参照。

## 6. 起動と終了

Windows版と Mac版は、実行ファイル（アプリケーションファイル）を実行するとアプリが起動します。

### 6.1 Windows版

`TaskMaster/` フォルダの `TaskMaster.exe` をダブルクリックして、起動します。

終了するときは、ウィンドウを閉じます。

### 6.2 Mac版(Zip)

`TaskMaster/` フォルダの `TaskMaster.app` をダブルクリック、起動します。

終了するときは、ウィンドウを閉じます。

Mac では初回の起動時に「"TaskMaster" は、開発元を検証できないため開けません」「"TaskMaster" は悪質なソフトウェアかどうかを Apple が確認できません」などの警告が出る。TaskMaster に Apple の署名と公証をしていないために出るもので、アプリが壊れているわけでもウイルスでもない。次のどれかの方法で一度許可すれば、次からは出ない。

macOS 15（Sequoia）以降：

1. `TaskMaster.app` をダブルクリックし、警告が出たら「完了」を押す。
2. 「システム設定」→「プライバシーとセキュリティ」を開き、下の方にある「"TaskMaster" は…ブロックされました」の横の「このまま開く」を押す。
3. 確認の画面で「開く」を押す。パスワードや Touch ID を求められることがある。

macOS 14 以前：`TaskMaster.app` を右クリック（Control を押しながらクリック）し、「開く」を選んで、確認の画面で「開く」を押す。

コマンドで許可する場合は、ターミナルで次を実行する。`/Applications/TaskMaster.app` の部分は、アプリを置いた場所に合わせます。

```bash
xattr -dr com.apple.quarantine /Applications/TaskMaster.app
```

### 6.3 Mac版(Homebrew)

「アプリケーション」フォルダの `TaskMaster.app` をダブルクリックする。Launchpad からも開ける。

終了するときは、ウィンドウを閉じる。

初回の起動時に警告が出たら、[6.2](#62-mac版zip) と同じ手順で許可する。コマンドで許可する場合は、パスを変えずに `xattr -dr com.apple.quarantine /Applications/TaskMaster.app` を実行すればよい。

### 6.4 Webアプリ版
- 起動手順
1. [インストール手順](#54-webアプリ版)でクローンした `task-master/apps/web` フォルダを開き、起動スクリプトを実行する。

   | 環境 | 起動スクリプト | 実行のしかた |
   |---|---|---|
   | Windows | `start.cmd` | ダブルクリックする |
   | Mac | `start.command` | Finder でダブルクリックする。初回だけ、右クリックして「開く」を選び、確認の画面で「開く」を押す |
   | Linux | `start.sh` | ターミナルで `./start.sh` を実行する |

2. 準備が終わるまで待つ。初回はライブラリのインストールとビルドがあるので、時間がかかる。準備ができるとブラウザが開く。開かない場合は、ブラウザで http://localhost:3001 を開く。

- 終了手順
1. 終了するときは、起動スクリプトのウィンドウで `Ctrl + C` を押すか、ウィンドウを閉じる。

## 7. 使い方

### 7.1 画面の見方

ウィンドウの左がサイドバー、右がメインエリアと呼びます。サイドバーで選んだ項目が、メインエリアに表示されます。

サイドバーには次の項目が並びます。

- 📊 ダッシュボード：全プロジェクトの集計（[7.10](#710-ダッシュボードと統計)）
- 📁 プロジェクト一覧：プロジェクトの作成・編集・アーカイブ・削除（[7.2](#72-プロジェクトを作る)、[7.11](#711-プロジェクトをアーカイブする)）
- プロジェクト名の一覧：クリックするとそのプロジェクトの画面が開く
- ⚙️ 設定（下部）：言語・ステータス遷移・祝日・タグ（[8 章](#8-設定)）

アーカイブ済のプロジェクトは、プロジェクト名の一覧に表示されません。

プロジェクトの画面は、上から次のように並ぶ。

- ヘッダー：プロジェクト名、統計を表示ボタン、ツリー / カンバン / ガントのビュー切り替えタブ、+ 新しいタスクボタン
- 統計情報：統計を表示ボタンが押された状態のときに表示される（[7.10](#710-ダッシュボードと統計)）
- フィルタバー：検索と絞り込み（[7.9](#79-検索と絞り込み)）
- タスクの一覧：選んだビュー（ツリービュー・カンバンビュー・ガントビュー）で表示する（[7.4](#74-ツリーカンバンガントのビュー切り替え)）

### 7.2 プロジェクトを作る

1. サイドバーの「📁 プロジェクト一覧」を開き、「+ 新しいプロジェクト」を押す
2. 名前・説明（省略可）・色を入力し、「作成」を押す
3. サイドバーにプロジェクト名が追加される。クリックするとプロジェクトの画面が開く

プロジェクト一覧の各プロジェクトにある「編集」でプロジェクトの名前・説明・色を変えらます。「削除」で削除できます。プロジェクトを削除すると、その中のタスクもすべて消えます。

### 7.3 タスクとサブタスクを作る

タスクを作るには、プロジェクトの画面の「+ 新しいタスク」を押すと、ダイアログが表示されます。次の項目を入力し、「作成」を押して、タスクを作ります。

| 項目 | 内容 |
|---|---|
| タイトル | 必須 |
| 説明 | 省略可 |
| ステータス | 設定画面で決めたステータスから選択する |
| 優先度 | 低・中・高・緊急から選択する、最初は「中」 |
| 開始日 | タスクの開始日をカレンダーで選ぶか直接入力する（「有効」にチェックを入れると、有効になる） |
| 期限 | タスクの期日（期限）をカレンダーで選ぶか直接入力する（「有効」にチェックを入れると、有効になる）|
| 親タスク | サブタスクにする場合に、親のタスクを選ぶ。「(なし・最上位)」の場合は、最上位のタスクになる |
| タグ | 付けるタグにチェックを付ける。下の欄に名前を入れて「追加」を押すと、新しいタグをその場で作れる |

「続けて作成」にチェックを付けて「作成」を押すと、ダイアログを閉じずに次のタスクを入力できます。

サブタスクは、ツリービューでタスクの行を右クリックし、「+ サブタスクを追加」を選んでも作ることができます。そのタスクを親にした状態でダイアログが開きます。サブタスクの下にさらにサブタスクを作ることもできます。

作ったタスクは、ツリービューで行をクリックするか、カンバンビューでカードをクリックするか、ガントビューでタスク名またはバーをダブルクリックすると、同じダイアログで編集できます。

### 7.4 ツリー・カンバン・ガントのビュー切り替え

プロジェクトの画面のヘッダーにあるツリー / カンバン / ガントで、ツリービュー（[7.5](#75-ツリービュー)）・カンバンビュー（[7.6](#76-カンバンビュー)）・ガントビュー（[7.7](#77-ガントビュー)）を切り替えます。

### 7.5 ツリービュー

- 親子関係のあるタスクはインデントを下げて、表示され、行の左の記号で、サブタスクを展開したり、畳んだりできる
- 行をクリックすると編集ダイアログが開く
- 行を右クリックすると、「+ サブタスクを追加」「編集」「ステータス変更」「削除」のメニューが出る
  - 「ステータス変更」なら、ダイアログを開かずにステータスだけを変えられる
  - タスクを削除すると、そのサブタスクも消える

### 7.6 カンバンビュー

- ステータスごとの列に、タスクをカードで表示し、列の並びは設定画面のステータスで決まる（[8.2](#82-ステータス遷移)）
- カードを別の列へドラッグすると、ステータスがその列のものに変わる
  - 同じ列の中で上下にドラッグすると、並び順が変わる
- カードをクリックすると編集ダイアログが開く

### 7.7 ガントビュー

- 行にタスクを、日付を列に表示する
- 開始日から期限までをステータスの色のバーで表示する
  - バーのを左右の端にドラッグすると、開始日と期限が一緒に動き、期間が変更される
- 土日と祝日（[8.3](#83-祝日)）は色を変えて表示する
- タスク名またはバーをダブルクリックすると編集ダイアログが開く

### 7.8 タスクの並べ替えと親の付け替え

ツリービューとガントビューの画面操作で、タスクの順番と親を変えられます。

カンバンビューではタスクの順番を変えられますが、親子関係は表示されません。

また、編集ダイアログの「親タスク」を選び直して親を変えることもできます。この場合、新しい親の最後のサブタスクになります。

### 7.9 検索と絞り込み

プロジェクトの画面のフィルタバーで、キーワード・ステータス・優先度・タグを組み合わせてタスクを絞り込むことができます。「クリア」を押すと、すべての条件が初期化されます。

### 7.10 ダッシュボードと統計

サイドバーの「📊 ダッシュボード」は、アーカイブしていない全プロジェクトの集計を表示します。

- 数値：プロジェクト数、直近7日の完了数、タスク総数、完了率、期限超過、期限が近い（今日から3日後まで）
- 期限超過のタスク、期限が近いタスク：それぞれ最大8件を、期限の早い順に表示する
- プロジェクトの一覧：名前・色・タスクの件数を表示する。クリックするとそのプロジェクトの画面が開く

プロジェクトの画面で「統計を表示」を押すと、そのプロジェクトだけの集計が表示されます。もう一度押すと隠れます。

どの集計でも、「完了」は設定画面で「完了として扱う」を付けたステータスで判断します。

### 7.11 プロジェクトをアーカイブする

プロジェクト一覧で「アーカイブ」を押すと、そのプロジェクトはサイドバーとダッシュボードに出なくなります。タスクなどのデータは消えません。

プロジェクト一覧で「アーカイブ済みも表示」にチェックを付けると、アーカイブしたプロジェクトも一覧に表示されます。「復元」を押すとアーカイブが解除され、もとに戻ります。

## 8. 設定

サイドバー下部の「⚙️ 設定」から設定画面を開き、設定を変更することができます。

### 8.1 言語 / Language

ボタン・メニュー・ダイアログ・エラーメッセージ等の表示言語を日本語か英語を選べます。ステータス名・タグ名・プロジェクト名など、自分で入力した内容は翻訳されません。

### 8.2 ステータス遷移

ステータスの追加（例：レビュー中）、名前と色の変更、並べ替え、削除ができます。ここでの並びがカンバンビューの列の並びになります。

- 「完了として扱う」を付けたステータスは、完了率や期限超過の計算で完了済みとして扱う
- タスクで使っているステータスと、最後の1件は削除できない（エラーが表示される）

### 8.3 祝日

ガントビューで休日として色を変える日を登録します。

- 日付（カレンダーで選ぶか直接入力）と名前を入れて「追加」を押す
- 一覧は日付の順に並ぶ。名前はその場で書き換えられ、削除もできる
- 「CSVから読み込む」で、CSV ファイルからまとめて登録できる
  - CSVの列は「日付,名称」の順
  - すでに登録してある日付の行は、名前を上書きする

配布 zip に入っている `holidays_sample.csv` は、2026年の祝日を入れた読み込みの例です。実際の祝日は公式の情報で確かめてください。

### 8.4 タグ

タグの作成、名前と色の変更、削除ができます。タグは全プロジェクトで共通です。

- 同じ名前のタグは作れない（エラーが表示される）
- 削除すると、それらのタスクからタグが外れる

## 9. データのバックアップとリストア手順

どの版も、データは1つの SQLite ファイルに保存されますので、バックアップはそのファイルをコピーし、リストアはコピーしておいたファイルを元の場所に戻します。

コピーや置き換えは、必ずアプリを終了してから行ってください。

**データのファイルを削除すると、データがすべて消えるため、操作に注意してください。**

### 9.1 Windows版

データは `TaskMaster.exe` と同じフォルダの `taskmaster.db` で、初めて起動したときに自動で作られます。

バックアップ：

1. TaskMaster を終了する
2. `taskmaster.db` を、別のフォルダや USB メモリなどにコピーする

リストア：

1. TaskMaster を終了する
2. 今の `taskmaster.db` を残したい場合は、別の名前にしておく
3. バックアップしたファイルを `TaskMaster.exe` と同じフォルダにコピーし、名前を `taskmaster.db` にする
4. TaskMaster を起動し、データが戻っていることを確かめる

### 9.2 Mac版

データは `~/Library/Application Support/TaskMaster/taskmaster.db` にあります。zip でも Homebrew でも場所は同じで、初めて起動したときに自動で作られます。このフォルダは、Finder の「移動」→「フォルダへ移動…」に `~/Library/Application Support/TaskMaster/` と入れると開けます。

バックアップ：

1. TaskMaster を終了する
2. `taskmaster.db` を、別のフォルダや外付けのディスクなどにコピーする

リストア：

1. TaskMaster を終了する
2. 今の `taskmaster.db` を残したい場合は、別の名前にしておく
3. バックアップしたファイルを `~/Library/Application Support/TaskMaster/` にコピーし、名前を `taskmaster.db` にする
4. TaskMaster を起動し、データが戻っていることを確かめる


### 9.3 Webアプリ版

データは、クローンした `task-master/apps/web` フォルダの `server/prisma/dev.db` にあります。`server/.env` の `DATABASE_URL` を変えている場合は、そこに書いた場所になります。

バックアップ：

1. サーバーを止める（起動スクリプトのウィンドウで `Ctrl + C` を押すか、ウィンドウを閉じる）
2. `dev.db` を、別のフォルダなどにコピーする

リストア：

1. サーバーを止める
2. 今の `dev.db` を残したい場合は、別の名前にしておく。
3. バックアップしたファイルを `server/prisma/` にコピーし、名前を `dev.db` にする
4. サーバーを起動し、ブラウザでデータが戻っていることを確かめる

## 10. 困ったとき

| 版 | 症状 | 対処 |
|---|---|---|
| Windows | 起動に失敗する | `Program Files` など書き込みできない場所に置いていると、データを保存できず起動しない。書き込めるフォルダに `TaskMaster/` フォルダごと移して、もう一度起動する。 |
| Windows | 起動したが、プロジェクトが1つも表示されない | エラーが出ていなければ正常である。最初はデータが空なので、プロジェクトを作る（[7.2](#72-プロジェクトを作る)）。サンプルのデータを見たい場合は [11.3](#113-サンプルデータ) を参照。 |
| Windows | 起動してもエラーが出る | エクスプローラーで `TaskMaster.exe` と同じフォルダを開き、`taskmaster.db` があるか確認する（[9.1](#91-windows版)）。ない場合はアプリをもう一度起動すると作られる。それでも作られない場合は、上の「起動に失敗する」を確認する。 |
| Windows | データを最初の状態に戻したい | アプリを終了してから、`TaskMaster.exe` と同じフォルダの `taskmaster.db` を削除する（データはすべて消える）。次に起動すると、空のデータで始まる。 |
| Mac | 「開発元を検証できない」などの警告が出て起動しない | zip 版は [6.2](#62-mac版zip)、Homebrew 版は [6.3](#63-mac版homebrew) の手順で許可する。 |
| Mac | 起動したが、プロジェクトが1つも表示されない | エラーが出ていなければ正常である。最初はデータが空なので、プロジェクトを作る（[7.2](#72-プロジェクトを作る)）。サンプルのデータを見たい場合は [11.3](#113-サンプルデータ) を参照。 |
| Mac | 起動してもエラーが出る | Finder で `~/Library/Application Support/TaskMaster/` を開き、`taskmaster.db` があるか確認する（[9.2](#92-mac版)）。ない場合はアプリをもう一度起動すると作られる。 |
| Mac | データを最初の状態に戻したい | アプリを終了してから、`~/Library/Application Support/TaskMaster/taskmaster.db` を削除する（データはすべて消える）。次に起動すると、空のデータで始まる。 |
| Webアプリ | `node -v` でエラーになる | Node.js 18 以上をインストールする。インストール後はターミナルを開き直す。 |
| Webアプリ | `EADDRINUSE` や「port 3001 is already in use」と出る | 3001 番のポートを別のプログラムが使っている。TaskMaster の起動スクリプトのウィンドウが残っていれば、`Ctrl + C` で止めてから起動し直す。止められない場合は、`server/.env` の `PORT=3001` を別の番号（例：`PORT=3002`）にして起動し、ブラウザで http://localhost:3002 を自分で開く。 |
| Webアプリ | 画面は出るが、エラーが出る・一覧が表示されない | 起動スクリプトのウィンドウが開いていて、`Server listening on http://localhost:3001` と出ているか確認する。http://localhost:3001/api/health を開いて `{"ok":true}` と出なければ、サーバーが動いていないので起動し直す。`server/prisma/dev.db`（[9.3](#93-webアプリ版)）がない場合も、起動スクリプトをもう一度実行すると作られる。 |
| Webアプリ | `Environment variable not found: DATABASE_URL` と出る | `server/.env` がない。起動スクリプトで起動すれば自動で作られる。手で起動した場合は、`server/.env.example` をコピーして名前を `.env` にする。 |

開発環境で動かしている場合（[11.2](#112-開発環境を整備するwindows版mac版)）は、次も確認する。

| 版 | 症状 | 対処 |
|---|---|---|
| Windows | `python --version` でエラーになる | Python 3.11 以上をインストールする。インストーラーで「Add python.exe to PATH」にチェックを入れる。インストール後はターミナルを開き直す。 |
| Windows | `ModuleNotFoundError` が出る | 仮想環境が有効になっていないか、ライブラリが入っていない。`.venv\Scripts\activate` で仮想環境を有効にしてから `pip install -e .` を実行する。 |
| Mac | `python3 --version` でエラーになる | Python 3.11 以上をインストールする（python.org のインストーラー、または `brew install python@3.12 python-tk@3.12`）。インストール後はターミナルを開き直す。 |
| Mac | `ModuleNotFoundError` が出る | 仮想環境が有効になっていないか、ライブラリが入っていない。`source .venv/bin/activate` で仮想環境を有効にしてから `pip install -e .` を実行する。 |
| Windows・Mac | ウィンドウが開かない、文字が化ける | Python が 3.11 以上か確認する。リモート接続など、画面を表示できない環境では動かない。 |

Webアプリ版のほかの対処は、[apps/web/README.md](./apps/web/README.md) を参照。

## 11. 開発者向け

### 11.1 動作環境と使用技術

| 項目 | 内容 |
|---|---|
| OS | Windows 10 / 11、macOS 12 以降 |
| 言語 | Python 3.11 以上 |
| 画面 | CustomTkinter（Tk） |
| データベース | SQLite（標準ライブラリの `sqlite3`。ファイルは `taskmaster.db`） |
| 主なライブラリ | customtkinter、charset-normalizer、Pillow |
| テスト | pytest（単体・結合・UI 部品・E2E） |
| 静的解析 | ruff |
| 配布 | Nuitka |

### 11.2 開発環境を整備する（Windows版・Mac版）

#### 11.2.1 Python を入れる

Python 3.11 以上が必要である。pip と Tk は Python に含まれているので、別に入れる必要はありません。

Windows：

1. https://www.python.org/downloads/ から Windows 用のインストーラーをダウンロードして実行する。
2. 最初の画面で「Add python.exe to PATH」に必ずチェックを入れてから、「Install Now」を押す。

PowerShell で `winget install Python.Python.3.12` を実行してもインストールできます。

Mac：https://www.python.org/downloads/ から macOS 用のインストーラー（`.pkg`）をダウンロードして実行する（Tk も入る）。Homebrew を使う場合は `brew install python@3.12 python-tk@3.12` を実行する。

インストールしたらターミナルを開き直し、次でバージョンが表示されることを確かめます。Mac では、この README のコマンドの `python` を `python3` に、`pip` を `pip3` に読み替えてください（仮想環境を有効にした後は `python` のままでよい）。

```bash
python --version
pip --version
```

#### 11.2.2 ソースコードを取得する

ソースコードを置きたいフォルダでターミナルを開き、次を実行します。

```bash
git clone https://github.com/ai-natsu/task-master.git
cd task-master/apps/desktop
```

Git を使わない場合は、GitHub のリポジトリのページで「Code」→「Download ZIP」を選んでダウンロードし、解凍してください。解凍してできた `apps/desktop` フォルダを使います。

`task-master/apps/desktop` フォルダ（`pyproject.toml` がある所）を、以下「リポジトリのフォルダ」と呼びます。11章のコマンドはすべて、リポジトリのフォルダで実行します。

- Windows：エクスプローラーでリポジトリのフォルダを開き、アドレスバーに `powershell` と入力して Enter を押す。または、フォルダ内の何もない所を右クリックして「ターミナルで開く」を選ぶ
- Mac：Finder でリポジトリのフォルダを右クリックし、「フォルダに新規ターミナル」を選ぶ

#### 11.2.3 仮想環境とライブラリを準備する（初回だけ）

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows（PowerShell・コマンドプロンプト）
source .venv/bin/activate       # Mac
pip install -e .
```

テストやビルドもする場合は、最後の行を `pip install -e .[dev]` にします。pytest・ruff・Nuitka などの開発用ツールも入ります。TODO:部品を再確認する。

仮想環境が有効になると、行頭に `(.venv)` と出る。ターミナルを開き直したときは、2回目以降も2行目か3行目のコマンドで仮想環境を有効にしてから作業します。以降のコマンドは、仮想環境が有効になっている前提です。

#### 11.2.4 起動と終了

```bash
python -m app.main
```

ウィンドウを閉じると終了します。

初回の起動でリポジトリのフォルダの直下に `taskmaster.db` が作られます。中身は配布版と同じで、ステータスの4件だけが入った空のデータです。

### 11.3 サンプルデータ

サンプルデータ（プロジェクト・タスク・タグ）を入れるには、次を実行します。

```bash
python seed.py
```

**既存のデータはすべて削除されるので、注意してください。** 

### 11.4 テストと静的解析

テストは「単体・結合」「UI 部品」「E2E」の3種類に分かれている。どれも一時ファイルのデータベースを使うので、`taskmaster.db` には触れず、`seed.py` も不要である。TODO：実行方法とテスト分類を再整理する。

| 種類 | コマンド | 内容 |
|---|---|---|
| 単体・結合 | `python -m pytest -m "not gui and not e2e"` | 画面を開かない速いテスト。純粋関数（ツリー・ドラッグ判定・ガント・期限判定・多言語・エラー文言）の単体テストと、データ層（SQLite）の結合テスト |
| UI 部品 | `python -m pytest tests/gui` | 入力欄の文字数の上限、フォームの必須の赤字、確認ダイアログなどを、実際の Tk のウィジェットで確かめる |
| E2E | `python -m pytest tests/e2e` | アプリ全体（`AppWindow`）を動かし、画面遷移・ダイアログ・確認ダイアログを確かめる（設計書の画面遷移表に対応） |
| すべて | `python -m pytest` | 上の3種類をまとめて実行する |

UI 部品と E2E のテストの実行中はウィンドウが表示されるので、マウスとキーボードに触らないこと。ディスプレイがない環境では、UI 部品のテストは自動でスキップされる。

よく使うオプション：

| やりたいこと | コマンド |
|---|---|
| 1つのファイルだけ実行する | `python -m pytest tests/integration/test_tasks_db.py` |
| テスト名の一部で絞り込む | `python -m pytest -k "cycle"`（E2E なら `python -m pytest tests/e2e -k "archive"`） |
| 詳しく表示する | `python -m pytest -v` |
| 最初の失敗で止める | `python -m pytest -x` |

静的解析は ruff で行う。エラーが0件であること。自動で直せるものは `python -m ruff check --fix .` で直す。

```bash
python -m ruff check .
```

### 11.5 ディレクトリ構成

```
task-master/
├─ apps/
│  ├─ web/               # Webアプリ版（Express・Prisma・React）
│  └─ desktop/           # デスクトップアプリ版（以下はこの中）
│     ├─ app/            # アプリ本体
│     │  ├─ main.py            # エントリポイント
│     │  ├─ constants.py       # 区分値（優先度）、入力欄の文字数の上限
│     │  ├─ models.py          # データクラス
│     │  ├─ i18n.py / locales/ # 多言語（日本語／英語）
│     │  ├─ db/                # SQLite を直接扱うデータ層（schema.sql を含む）
│     │  ├─ logic/             # ツリー構築・ドラッグ判定・ガント計算・期限判定（純粋関数）
│     │  ├─ ui/                # CustomTkinter の画面・部品
│     │  └─ assets/            # アイコン
│     ├─ tests/
│     │  ├─ unit/              # 単体テスト
│     │  ├─ integration/       # 結合テスト（データ層 + SQLite）
│     │  ├─ gui/               # UI 部品のテスト
│     │  └─ e2e/               # 画面遷移の E2E
│     ├─ packaging/      # exe・.app・配布 zip の作成（build_exe.py / build_zip.py など）
│     ├─ seed.py         # サンプルデータの投入（既存データを全削除する）
│     └─ pyproject.toml  # プロジェクト設定（依存ライブラリ、ruff、pytest）
├─ shared/               # 両アプリで共有するもの（design / assets / contracts）
├─ Casks/                # Homebrew の Cask（taskmaster.rb。brew tap が直下を読むため、ここに置く）
├─ .github/              # GitHub Actions のワークフロー
├─ LICENSE
└─ README.md
```

データベース（`taskmaster.db`）、仮想環境（`.venv/`）、ビルドの出力（`packaging/dist/`）は Git に含めない。
