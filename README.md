# TaskMaster

プロジェクト・タスク・サブタスク（無制限階層）・タグ・優先度・期限を管理できるデスクトップ版のタスク管理アプリ。単一の `TaskMaster.exe` で動くため、利用者に Python などのインストールや、別途サーバーは不要。カンバンビュー、ガントチャートビュー、タスクツリーを切り替えて進捗管理できるので使いやすい。検索/フィルタ、ドラッグ&ドロップによる並び替え、統計ダッシュボードを備える。画面の表示言語は日本語／英語を切替できる。

## 1. 画面説明

### 1.1 共通レイアウト

| 要素 | 内容 |
|---|---|
| サイドバー | ダッシュボード／プロジェクト一覧画面／設定へのリンク、プロジェクト名の一覧（アーカイブ済みは非表示） |
| メインエリア | 選択中の画面を表示 |

### 1.2 ダッシュボード

全プロジェクト横断の概要画面。

- 統計カード：プロジェクト数（アーカイブ除く）、直近7日の完了数、タスク総数、完了率、期限超過、期限が近い（本日〜3日後の4日間）
- 期限超過タスク一覧（最大8件、期限が近い順）
- 期限が近いタスク一覧（最大8件）
- プロジェクトカード（プロジェクト名・色・タスク件数、クリックで詳細へ）

### 1.3 プロジェクト一覧

- 「+ 新しいプロジェクト」ボタンからプロジェクトを作成
- プロジェクトごとに 編集／アーカイブ・復元／削除
- アーカイブしたプロジェクトはサイドバー・ダッシュボードから非表示になる（「アーカイブ済みも表示」チェックで表示し、復元できる）

### 1.4 プロジェクト詳細

- ヘッダー：プロジェクト名・「ツリー / カンバン / ガント」表示切替・「統計を表示」トグル・「+ 新しいタスク」ボタン
- 統計表示（トグルで開閉、このプロジェクトに絞った集計）
- フィルタバー：キーワード検索、ステータス、優先度、タグで絞り込み（複合可）
- カンバンビュー：
  - ステータスごとの列にタスクカードを表示（列は設定画面で自由に増減可）
  - カードを別の列へドラッグ&ドロップするとステータス変更、同じ列内でドラッグすると並び順を変更
  - カードのクリックで編集ダイアログが開く（ドラッグ中はカード全体が追従する）
- ガントチャートビュー：
  - タスクを行、日付を列として、開始日〜期限の期間をステータス色のバーで表示
  - 月・日ヘッダー（土日・祝日は色分け）、今日のハイライトと縦ライン
  - バー中央のドラッグで開始日・期限を平行移動、バー両端のドラッグで期間を伸縮、行名のドラッグで並べ替え・親の付け替え
  - タスク名・バーのダブルクリックで編集ダイアログが開く（シングルクリックでは何も起きない）
- タスクツリー：
  - 親子関係を持つタスクを無制限の深さでネスト表示
  - 行のクリックで編集ダイアログが開く。右クリックのメニュー：サブタスク追加・編集・ステータス変更・削除
  - ドラッグで並び替え・親の付け替え（行の上端・下端は兄弟として挿入、中央は子にする）
  - 展開／折りたたみ
- タスク作成・編集ダイアログ：タイトル・詳細・ステータス・優先度・開始日・期限・親タスク（循環は拒否）・タグ（複数選択＋その場で新規作成、右クリックで削除）
- プロジェクト作成・編集ダイアログ：名前・説明・カラー選択
- 削除・アーカイブの確認ダイアログ

### 1.5 設定

サイドバー下部の「⚙️ 設定」から開く。

- ステータス設定：ステータスの追加・名称変更・カラー変更・並び替え・削除
- 「完了として扱う」フラグ：付けたステータスは完了率の計算や期限超過の判定で完了済みとして扱われる
- タスクで使用中のステータス、および最後の1件は削除不可（エラーメッセージ表示）
- 祝日：日付（カレンダー／直接入力）・名称を登録。一覧は日付昇順で、名称のインライン編集・削除ができる。CSV（列順「日付,名称」）の一括登録にも対応し、日付が一致する行は名称を上書きする。取り込みの例として、配布 zip に 2026 年分の祝日を入れた `holidays_sample.csv` が入っている（実際の暦は、公式の情報で確認すること）
- タグ：プロジェクトを横断して共有される名前・色の一覧。改名・色変更・削除ができる（削除確認ダイアログに付与タスク件数を表示）。名前の重複はエラーで拒否
- 言語 / Language：表示言語を日本語／英語から選択（即時反映、次回起動時も保持）。ステータス名・タグ名・プロジェクト名などユーザーが入力したデータは翻訳されない

## 2. 技術要件

### 2.1 使用技術

| 項目 | 採用技術 |
|---|---|
| 言語 | Python 3.11 以上 |
| 画面 | CustomTkinter（Tk） |
| データベース | SQLite（標準ライブラリの `sqlite3`。ファイルは `taskmaster.db`） |
| 主なライブラリ | customtkinter、charset-normalizer、Pillow |
| テスト | pytest（単体・結合・UI 部品・E2E） |
| 静的解析 | ruff |
| 配布 | Nuitka |

### 2.2 動作要件

- Windows 10 / 11、または Mac（macOS 12 以降）
- 配布版は、Python などのインストールが不要。ソースから動かす場合は、Python 3.11 以上が必要（5 章）。

## 3. 配布とデータの保存場所

### 3.1 配布方式

- 配布は **zip**。OS ごとに、別の zip がある。
  - **Windows：** 解凍すると `TaskMaster/` フォルダができ、その中の `TaskMaster.exe` をダブルクリックするだけで起動する（インストール不要）。
  - **Mac：** 解凍すると `TaskMaster/` フォルダができ、その中の `TaskMaster.app` をダブルクリックするだけで起動する（インストール不要）。
- zip の中身：
  - `TaskMaster.exe`（Windows）／ `TaskMaster.app`（Mac）
  - `README.txt`（利用者向け。起動方法・データの保存場所・バックアップ方法）
  - `LICENSE.txt`（TaskMaster のライセンス）
  - `THIRD_PARTY_NOTICES.txt`（利用ライブラリのライセンス表記）
  - `holidays_sample.csv`（祝日 CSV の例）

### 3.2 データの保存場所

データは、`taskmaster.db` に保存される。初回起動時に、次の場所に自動で作成される。

| OS | 保存場所 |
|---|---|
| Windows | `TaskMaster.exe` と同じフォルダ |
| Mac | `~/Library/Application Support/TaskMaster/`（Finder で「移動」→「フォルダへ移動…」に、このパスを入力すると開ける） |

- バックアップや別の PC への移行は、アプリを終了してから `taskmaster.db` をコピーするだけでよい。
- `taskmaster.db` を削除するとデータがすべて消える。
- アプリを入れ替えるときは、Windows は `taskmaster.db` を残したまま `TaskMaster.exe` だけを差し替える。Mac は `TaskMaster.app` だけを差し替える（データは別の場所にあるので、消えない）。
- （Windows）`Program Files` など書き込みできない場所には置かないこと（データを保存できず起動に失敗する）。

## 4. 始め方（利用者向け）

配布版を使う場合の手順。Python などのインストールは不要。

### 4.1 インストール手順

**Windows**

1. 配布の zip（`TaskMaster-<版>-win64.zip`）を解凍する。`TaskMaster/` フォルダができる。
2. `TaskMaster/` フォルダを、**任意の場所**に置く。

**Mac（zip を使う場合）**

1. 配布の zip（`TaskMaster-<版>-mac.zip`）を解凍する。`TaskMaster/` フォルダができる。
2. `TaskMaster/` フォルダを、**任意の場所**に置く。

**Mac（Homebrew の Cask を使う場合）**

[Homebrew](https://brew.sh/)（Mac のパッケージ管理ツール）が入っていること。ターミナルで、次のコマンドを実行する（どのフォルダで実行してもよい）。

```bash
brew tap ai-natsu/task-master https://github.com/ai-natsu/task-master
brew install --cask taskmaster
```

`TaskMaster.app` が、「アプリケーション」フォルダ（`/Applications`）にインストールされる。

| やりたいこと | コマンド |
|---|---|
| 新しい版にする | `brew upgrade --cask taskmaster` |
| アンインストールする（データは残る） | `brew uninstall --cask taskmaster` |
| アンインストールし、データも消す | `brew uninstall --zap --cask taskmaster` |

### 4.2 起動手順

- **Windows：** `TaskMaster/` フォルダの中の `TaskMaster.exe` をダブルクリックする。
- **Mac（zip）：** `TaskMaster/` フォルダの中の `TaskMaster.app` をダブルクリックする。
- **Mac（Homebrew）：** 「アプリケーション」フォルダの `TaskMaster.app` を、ダブルクリックする（Launchpad からも開ける）。

終了するときは、ウィンドウを閉じる。データの保存場所は、3.2 を参照。

#### 4.2.1 Mac で警告が出るとき

**Mac では、初回の起動で、警告が表示される。** 「"TaskMaster" は、開発元を検証できないため開けません」「"TaskMaster" は悪質なソフトウェアかどうかを Apple が確認できません」などである。TaskMaster のアプリに、Apple の署名・公証をしていないために出る警告で、故障や、ウイルスではない。次の手順で、1 回だけ許可すれば、2 回目からは、警告が出ない。

- **macOS 15（Sequoia）以降：**
  1. `TaskMaster.app` をダブルクリックして、警告が出たら、「完了」を押す。
  2. 「システム設定」→「プライバシーとセキュリティ」を開き、下の方の「"TaskMaster" は、…ブロックされました」の横の「このまま開く」を押す。
  3. 確認の画面で、「開く」を押す（パスワードや Touch ID を求められることがある）。
- **macOS 14 以前：** `TaskMaster.app` を右クリック（Control を押しながらクリック）→「開く」→ 確認の画面で「開く」。
- **コマンドで許可する場合：** 次のコマンドを実行する（Homebrew の Cask でも、同じ）。

```bash
xattr -dr com.apple.quarantine /Applications/TaskMaster.app
```

（`/Applications/TaskMaster.app` は、アプリを置いた場所に変える。）

## 5. 始め方（開発者向け）

ソースコードから動かす方法を示す。配布版を使う場合は、この章は不要（3 章を参照）。

### 5.1 インストール手順

#### 5.1.1 必要なソフト

| ソフト | 内容 | 備考 |
|---|---|---|
| Python 3.11 以上（Windows / Mac） | TaskMaster を動かすための実行環境 | **pip（ライブラリの管理ツール）と、画面の部品（Tk）は、Python に同梱される**ので、別にインストールする必要はない |
| Git（任意） | ソースコードの取得に使う | ZIP でダウンロードする場合は不要 |

#### 5.1.2 Python のインストール

**Windows**

1. https://www.python.org/downloads/ を開き、「Download Python 3.x」のボタンから、Windows 用のインストーラーをダウンロードする。
2. ダウンロードしたファイルを実行する。最初の画面で、**「Add python.exe to PATH」に必ずチェックを入れて**から、「Install Now」を押す。
3. インストール後、**ターミナルを開き直す**（次の確認コマンドを認識させるため）。

コマンドでインストールする場合（PowerShell。**どのフォルダで実行してもよい**）：

```bash
winget install Python.Python.3.12
```

**インストールの確認**

ターミナルで（**どのフォルダでもよい**）次を実行し、バージョンが表示されればよい（3.11 以上）。

```bash
python --version      # 例：Python 3.12.7
pip --version
```

**Mac**

1. https://www.python.org/downloads/ から、macOS 用のインストーラー（`.pkg`）をダウンロードして実行する（Tk も入る）。
2. または、Homebrew を使っている場合：`brew install python@3.12 python-tk@3.12`
3. インストール後は、**ターミナルを開き直す**。確認は、`python3 --version` と `pip3 --version`（Mac では、`python` の代わりに `python3`、`pip` の代わりに `pip3` と入力する）。

#### 5.1.3 ソースコードの入手

どちらかの方法で、ソースコードを入手する。

**実行する場所：** ソースコードを置きたいフォルダ（例：`C:\Users\あなたの名前\work`）でターミナルを開いて実行する。実行すると、そのフォルダの中に `task-master` フォルダができる。**この `task-master` フォルダが、以降の「クローンしたリポジトリのルートディレクトリ」である。**

```bash
git clone https://github.com/ai-natsu/task-master.git
cd task-master
git checkout develop/v2
```

または、GitHub のリポジトリのページで、ブランチを `develop/v2` にして「Code」→「Download ZIP」を選び、ダウンロードした ZIP を解凍する。

#### 5.1.4 ターミナルの開き方

以降のコマンドは、**クローンしたリポジトリのルートディレクトリ**（`pyproject.toml` と `README.md` があるフォルダ。ZIP でダウンロードした場合は、解凍したフォルダ）で、ターミナルを開いて実行する。

- **Windows：** エクスプローラーでそのフォルダを開き、アドレスバーに `powershell` と入力して Enter を押す。または、フォルダの何もない所を右クリックして「ターミナルで開く」を選ぶ。
- **Mac：** Finder でそのフォルダを右クリックし、「フォルダに新規ターミナル」を選ぶ（または、ターミナルを開いて `cd フォルダのパス` を実行する）。

#### 5.1.5 ライブラリのインストール（初回だけ）

**実行する場所：** クローンしたリポジトリのルートディレクトリ（5.1.4）。次のコマンドの 1 行目で、そのフォルダに移動する。

```bash
cd <リポジトリのルートフォルダ>
python -m venv .venv                 # 仮想環境（この README の手順専用の、Python のライブラリ置き場）を作る（Mac は python3）
.venv\Scripts\activate               # Windows：仮想環境を有効にする（PowerShell / コマンドプロンプト）
source .venv/bin/activate            # Mac：仮想環境を有効にする
pip install -e .                     # TaskMaster と、必要なライブラリをインストールする
```

テストやビルドも行う場合は、最後の行を `pip install -e .[dev]` にする（pytest・ruff・Nuitka などの開発用ツールも入る）。

仮想環境を有効にすると、行頭に `(.venv)` と表示される。**新しくターミナルを開いたときは、コマンドを実行する前に、仮想環境を有効にする**（Windows は `.venv\Scripts\activate`、Mac は `source .venv/bin/activate`）。

### 5.2 起動手順

#### 5.2.1 起動する

5.1.5 の準備が済んでいること。以下のコマンドを実行すると、TaskMaster のウィンドウが開く。

```bash
cd <リポジトリのルートフォルダ>
.venv\Scripts\activate               # Windows
source .venv/bin/activate            # Mac
python -m app.main
```

初回は、リポジトリ直下に `taskmaster.db`（データベース）を作成する。

#### 5.2.2 停止する

TaskMaster のウィンドウを閉じる。

#### 5.2.3 初期のデータとサンプルデータ

- **初期のデータベースは空**である（プロジェクト・タスク・タグ・祝日は 0 件）。ステータス（未着手・進行中・完了・取下げ）の 4 件だけが、起動時に自動で入る（ステータスが 1 件も無いときだけ）。
- 配布版も、初回起動時に同じ状態のデータベースを作る。

サンプルデータを入れたい場合は、以下のコマンドを実行する（既存のデータは全削除される。実際のデータが入っているデータベースでは実行しない）。

```bash
cd <リポジトリのルートフォルダ>
.venv\Scripts\activate               # Windows
source .venv/bin/activate            # Mac
python seed.py
```

- `seed.py` は、**手動で、必要なときだけ**実行する。自動では実行されない。
- テストは、一時ファイルの専用データベースを使うので、seed は不要で、`taskmaster.db` にも触れない。

#### 5.2.4 うまくいかないとき

| 症状 | 対処 |
|---|---|
| Python が見つからない（`python --version`（Mac は `python3 --version`）でエラーになる） | Python をインストールする（5.1.2）。Windows は、インストーラーの **「Add python.exe to PATH」にチェックを入れる**。インストール後は、ターミナルを開き直す |
| `ModuleNotFoundError` | ライブラリが入っていない、または仮想環境が有効でない。5.1.5 の手順で仮想環境を有効にして、`pip install -e .` を実行する |
| ウィンドウが開かない・文字が化ける | Python 3.11 以上か、Windows または Mac か確認する。リモート接続など、画面を表示できない環境では動かない |
| データを初期状態に戻したい | TaskMaster を終了してから、`taskmaster.db` を削除する。場所は、ソースから動かしている場合はリポジトリ直下、配布版は 3.2 の表のとおり。次に起動すると、空のデータベースが作られる |
| サンプルデータを入れたい | 5.2.3 のコマンドを実行する（既存のデータは全削除される） |

#### 5.2.5 起動しても、エラーが出る・データが表示されないとき

アプリのウィンドウは開くのに、エラーが出る、またはプロジェクトの一覧が表示されない場合は、次の順で確認する。**コマンドは使わず、フォルダとファイルの確認だけで行える。**

**手順 1：データベースのファイルがあるか確認する**

1. ファイルを見るアプリ（Windows はエクスプローラー、Mac は Finder）で、データベースのファイル **`taskmaster.db`** がある場所を開く。ソースから動かしている場合は**リポジトリのルートフォルダ**、配布版は 3.2 の表の場所である。
2. `taskmaster.db` があるか確認する。
   - **ある場合：** 手順 3 に進む。
   - **ない場合：** データベースがまだ作られていない。アプリを**もう一度起動する**と、自動で作られる。作られない場合は、手順 2 に進む。

**手順 2：書き込める場所に置いているか確認する（Windows）**

**（Windows のみ）** 配布版を `Program Files` など、書き込みできない場所に置くと、データベースを作れず、起動に失敗する。書き込めるフォルダに `TaskMaster.exe` を移して、もう一度起動する。

**手順 3：エラーではなく、データが空なだけでないか確認する**

エラーの表示が出ておらず、一覧に何も表示されないだけの場合は、**正常な状態**である。初期のデータベースは空なので、画面から作成する（6.1）。サンプルのデータで確認したい場合は、5.2.3 の「サンプルデータを入れたい場合」を行う。

## 6. 使い方

起動するとウィンドウが開く。初期のデータベースは空なので、最初にプロジェクトを作る。サンプルデータを入れた場合（5.2.3）は、サンプルのプロジェクト・タスクが入った状態で確認できる。

### 6.1 プロジェクトを作る

1. サイドバーの「📁 プロジェクト一覧」を開き、「+ 新しいプロジェクト」をクリック
2. 名前・説明（任意）・カラーを選んで「作成」
3. サイドバーに追加されたプロジェクト名をクリックするとプロジェクト詳細画面に移動する

### 6.2 タスクを作る

1. プロジェクト詳細画面右上の「+ 新しいタスク」をクリック
2. タイトル（必須）、詳細、ステータス、優先度、期限、タグを入力して「作成」
3. タグは既存のものをクリックして選択するか、下の入力欄に新しいタグ名を入れて「追加」するとその場で新規作成される

### 6.3 サブタスクを作る

ツリー表示で、タスクの行を右クリックして「+ サブタスクを追加」を選ぶと、そのタスクの子タスクとして新規作成ダイアログが開く（Mac は、マウスの副ボタン、または Control を押しながらクリック）。サブタスクにさらにサブタスクを追加でき、階層に制限はない（無制限階層）。

既存タスクの親を変更したい場合は、そのタスクを編集し、フォーム内の「親タスク」欄で移動先を選び直す（自分自身やその子孫は選択肢から除外される）。

### 6.4 ステータスを更新する

ツリー表示で、タスクの行を右クリックして「ステータス変更」を選ぶと、編集ダイアログを開かずに、その場でステータス（未着手／進行中／完了など）を更新できる。

### 6.5 並び替える

ツリーの行（ガントの行名）をドラッグすると、並び順を変更できる。行の上端・下端へ落とすと兄弟として挿入され、中央へ落とすと子になる（自分自身の配下には移動できない）。親を変更したい場合は、編集ダイアログの「親タスク」でも変更できる。

### 6.6 カンバンで管理する

プロジェクト画面上部の切替タブの「カンバン」を押すとステータスごとの列表示に切り替わる。

- カードを**別の列へドラッグ** → ステータスがその列のものに変わる
- カードを**同じ列内で上下にドラッグ** → 並び順（優先順）が変わる
- カードをクリック → 編集ダイアログが開く

### 6.7 ガントチャートで見る

プロジェクト画面上部の切替タブの「ガント」を押すと、開始日〜期限をバーで表すガントチャートに切り替わる。開始日はタスクの作成・編集ダイアログの「開始日」で設定する。今日の位置には縦ラインが表示される。バーを左右にドラッグすると開始日と期限が一緒に動き、バーの端をドラッグすると期間だけが変わる。バーまたはタスク名をダブルクリックすると、編集ダイアログが開く。

### 6.8 プロジェクトをアーカイブする

プロジェクト一覧画面では編集・削除のほか「アーカイブ」ができる。アーカイブするとサイドバーやダッシュボードに表示されなくなる（データは残る）。「アーカイブ済みも表示」にチェックを入れると表示され、「復元」で元に戻せる。

### 6.9 ステータスを自分用に変える

サイドバー下部の「⚙️ 設定」→「ステータス設定」で、ステータスの追加（例: レビュー中）・名称/色の変更・並び替え・削除ができる。「完了として扱う」を付けたステータスが完了率などの集計で「完了」と見なされる。同じ画面で、祝日（個別の追加・CSV の一括読み込み）とタグ（改名・色の変更・削除）も管理できる。

### 6.10 表示言語を切り替える

サイドバー下部の「⚙️ 設定」→「言語 / Language」で日本語／英語を選ぶ。選んだ言語は、次回起動時も保持される。ステータス名やタグ名など、ご自身で入力した内容は翻訳されない。

### 6.11 検索・絞り込み

プロジェクト詳細画面のフィルタバーで、キーワード検索・ステータス・優先度・タグを組み合わせて絞り込める。「クリア」ですべてリセット。

### 6.12 統計を見る

- プロジェクト詳細画面の「統計を表示」で、そのプロジェクトに絞った完了率・期限超過件数などを表示
- サイドバーの「ダッシュボード」では、全プロジェクト横断の統計と、期限超過／期限が近いタスクの一覧を確認できる

## 7. テスト手順

テストは、**単体・結合**、**UI 部品**、**E2E** の 3 つに分かれていて、それぞれ別のコマンドで実行する。実行する前に、開発用のツール（pytest など）をインストールしておく（`pip install -e .[dev]`、5.1.5）。

**実行する場所：** この章のコマンドは、**クローンしたリポジトリのルートディレクトリ**（5.1.4）で、**仮想環境を有効にした状態**で実行する。各コマンドの前に、そのフォルダへ移動するコマンドと、仮想環境を有効にするコマンドを書いている。

詳細（種類・置き場所・方針・入力値の上限）は、[テスト設計書](docs/TEST_DESIGN.md) を参照。

### 7.1 単体・結合テスト

画面を開かない、速いテスト。純粋関数（ツリー・ドラッグ判定・ガント・期限判定・多言語・エラー文言）の単体テストと、データ層（SQLite）の結合テストを検証する。

```bash
cd <リポジトリのルートフォルダ>
.venv\Scripts\activate               # Windows
source .venv/bin/activate            # Mac
python -m pytest -m "not gui and not e2e"
```

| やりたいこと | コマンド（ルートディレクトリで、仮想環境を有効にして実行する） |
|---|---|
| 1 ファイルだけ実行する | `python -m pytest tests/integration/test_tasks_db.py` |
| テスト名の一部で絞り込む | `python -m pytest -k "cycle"` |
| 詳しい表示で実行する | `python -m pytest -v` |
| 最初の失敗で止める | `python -m pytest -x` |

結合テストは、テストごとに一時ファイルのデータベースを作り、開発用の `taskmaster.db` には触れない。

### 7.2 UI 部品のテスト

画面の部品（入力欄の文字数の上限、フォームの必須の赤字、確認ダイアログなど）を、実際の Tk のウィジェットで検証する。

1. 実行中は、**ウィンドウが一瞬表示される**。マウス・キーボードの操作を控える。
2. 次のコマンドを実行する。

```bash
cd <リポジトリのルートフォルダ>
.venv\Scripts\activate               # Windows
source .venv/bin/activate            # Mac
python -m pytest tests/gui
```

画面を開けない環境（ディスプレイが無い環境など）では、自動でスキップされる。

### 7.3 E2E テスト

アプリ全体（`AppWindow`）を実際に動かして、画面遷移・モーダル・確認ダイアログを検証する（設計書の画面遷移表に対応）。

1. 実行中は、**ウィンドウが表示される**。マウス・キーボードの操作を控える。
2. 次のコマンドを実行する。

```bash
cd <リポジトリのルートフォルダ>
.venv\Scripts\activate               # Windows
source .venv/bin/activate            # Mac
python -m pytest tests/e2e
```

| やりたいこと | コマンド（ルートディレクトリで、仮想環境を有効にして実行する） |
|---|---|
| 全部（単体・結合・UI 部品・E2E）を実行する | `python -m pytest` |
| テスト名の一部で絞り込む | `python -m pytest tests/e2e -k "archive"` |

E2E は、一時ファイルのデータベースを使い、`taskmaster.db` には触れない。

### 7.4 静的解析（ruff）

```bash
cd <リポジトリのルートフォルダ>
.venv\Scripts\activate               # Windows
source .venv/bin/activate            # Mac
python -m ruff check .
```

エラーが 0 件であること。自動で直せるものは、`python -m ruff check --fix .` で直す。

## 8. ディレクトリ構成

```
/（クローンしたリポジトリのルートディレクトリ）
├─ app/                  # アプリ本体
│  ├─ main.py            # エントリポイント
│  ├─ constants.py       # 区分値（優先度）、入力欄の文字数の上限
│  ├─ models.py          # データクラス
│  ├─ i18n.py / locales/ # 多言語（日本語／英語）
│  ├─ db/                # SQLite を直接扱うデータ層（schema.sql を含む）
│  ├─ logic/             # ツリー構築・ドラッグ判定・ガント計算・期限判定（純粋関数）
│  ├─ ui/                # CustomTkinter の画面・部品
│  └─ assets/            # アイコン
├─ tests/
│  ├─ unit/              # 単体テスト
│  ├─ integration/       # 結合テスト（データ層 + SQLite）
│  ├─ gui/               # UI 部品のテスト
│  └─ e2e/               # 画面遷移の E2E
├─ packaging/            # exe・.app・配布 zip の作成（build_exe.py / build_zip.py など）
├─ Casks/                # Homebrew の Cask（Mac 用のインストールの定義：taskmaster.rb）
├─ docs/                 # 設計書
├─ seed.py               # サンプルデータの投入（既存データを全削除する）
└─ pyproject.toml        # プロジェクト設定（依存ライブラリ、ruff、pytest）
```

データベース（`taskmaster.db`）、仮想環境（`.venv/`）、ビルドの出力（`packaging/dist/`）は Git に含めない。
